# Eye Care Reminder 手工验收清单

## 1. 构建与加载

1. 在项目根目录运行：

```bash
npm install
npm test -- --run
npx tsc --noEmit
npm run build
```

2. 打开 `chrome://extensions`
3. 开启 `开发者模式`
4. 点击 `加载已解压的扩展程序`
5. 选择项目里的 `dist/`

验收标准：

- 扩展可以正常加载
- 没有 manifest 错误
- popup 可以打开
- options 页面可以打开

## 2. 无额外权限打扰

1. 打开任意普通网页
2. 再打开微信读书阅读页 `https://weread.qq.com/web/reader/...`
3. 观察整个过程中是否出现意外的权限请求或模式切换提示

验收标准：

- 不应出现额外权限请求
- 不应出现旧版本功能或模式切换相关文案
- 只有在普通网页里主动点击 `在此站点启用护眼提醒` 时，才允许出现权限请求

## 3. 受限页面检测

1. 打开 `chrome://extensions`、`chrome://settings` 或其他受限页面
2. 点击扩展图标

验收标准：

- 不显示 `在此站点启用护眼提醒` 按钮
- popup 中存在 `提醒设置` 按钮
- `预览提醒` 按钮置灰
- popup 的阅读状态显示 `不可用`
- popup 的状态解释显示 `当前页面暂不支持启用护眼提醒`

## 4. 普通网页未启用状态

1. 打开任意普通网页，例如 `https://example.com`
2. 点击扩展图标

验收标准：

- 显示 `在此站点启用护眼提醒` 按钮
- `预览提醒` 按钮置灰
- popup 的阅读状态显示 `未启用`
- popup 的下次提醒显示 `授权后可用`
- popup 的状态解释显示 `授权后会在当前站点开始计时和提醒`

## 5. 普通网页启用当前站点

1. 打开任意普通网页，例如 `https://example.com`
2. 点击扩展图标
3. 点击 `在此站点启用护眼提醒`
4. 在浏览器权限弹窗中选择允许
5. 等 popup 刷新后再次观察状态

验收标准：

- 会出现当前站点的权限请求
- 授权成功后，启用按钮消失
- `预览提醒` 按钮变为可用
- 当前站点后续刷新后仍保持已授权

## 6. 权限拒绝

1. 打开一个尚未授权的普通网页
2. 点击 popup 中的 `在此站点启用护眼提醒`
3. 在浏览器权限弹窗中选择拒绝

验收标准：

- popup 保持未启用状态
- `预览提醒` 按钮仍置灰
- 不出现脚本注入报错导致的白屏或卡死

## 7. 微信读书默认支持与回归

1. 打开一个微信读书阅读页
2. 点击扩展图标

验收标准：

- 不显示 `在此站点启用护眼提醒`
- `预览提醒` 按钮可用
- popup 中存在 `提醒设置` 按钮
- 微信读书里的书名识别仍正常工作

## 8. 预览提醒

1. 打开一个已启用页面
2. 点击 popup 中的 `预览提醒`

验收标准：

- 当前页面会按设置出现提醒
- 开启全屏提醒时，底层页面不能继续点击或滚动
- 开启语音时，会播放扩展内置固定语音
- `20-20-20` 模式下，关闭按钮会先经历 `20 秒` 倒计时
- `标准提醒` 模式下，可以立即点击 `我知道了` 关闭
- 今日提醒次数不增加
- 下次提醒时间不变化

## 9. 活跃阅读累计

1. 打开一个已启用页面
2. 保持标签页在前台
3. 每隔一段时间做一次滚动、点击、按键或滚轮操作
4. 打开 popup 观察状态

验收标准：

- 阅读状态显示 `计时中 · X分YY秒`
- popup 中显示 `正在累计活跃阅读时间`
- 下次提醒显示倒计时
- 今日阅读时长会逐步增加

## 10. 非活跃暂停

1. 在已启用页面累计几分钟阅读后
2. 切到其他标签页，或让当前页超过 `3 分钟` 没有任何操作
3. 打开 popup

验收标准：

- 阅读状态变为 `已暂停 · X分YY秒`
- 切到其他标签页后，popup 解释为 `页面不在前台，返回后继续计时`
- 超过 `3 分钟` 无操作后，popup 解释为 `最近 3 分钟没有阅读操作`
- 下次提醒显示 `等待开始阅读`
- 不应继续累计阅读时间

## 11. 真实提醒

1. 在已启用页面保持活跃阅读累计达到当前设置的提醒间隔
2. 观察页面提醒

验收标准：

- 页面会按设置出现提醒
- 开启全屏提醒时，底层页面不能继续点击或滚动
- `20-20-20` 模式下，关闭按钮会先经历 `20 秒` 倒计时
- 开启语音时：
  - `20-20-20` 模式文案为 `请休息一下，看向 20 英尺外至少 20 秒，顺便多眨眼几次。`
  - `标准提醒` 模式文案为 `请休息一下，眨眼几次，再看远处十秒。`
- 提醒出现后，下一轮累计重新开始
- popup 中的今日提醒次数加 `1`

## 12. 累计暂停后继续

1. 先活跃阅读 `10 分钟`
2. 切走标签页 `5 分钟`
3. 回来继续活跃阅读 `10 分钟`

验收标准：

- 切走期间不累计
- 回来继续读满第二个 `10 分钟` 后触发提醒

## 13. 固定音频失败时的退化

如果你能方便制造音频播放失败的场景，执行：

1. 打开一个已启用页面
2. 触发一次预览提醒，或等待真实提醒

验收标准：

- 页面全屏提醒仍会出现
- 不会自动退回到系统 `TTS`
- 扩展不会因为音频失败而报错或停止计时

## 14. 固定音频播放状态

1. 打开一个已启用页面
2. 点击 `预览提醒`
3. 在页面 DevTools Console 中检查：

```js
document.documentElement.dataset.wereadEyeCareReminderAudioPath
document.documentElement.dataset.wereadEyeCareReminderAudioStatus
document.documentElement.dataset.wereadEyeCareReminderAudioErrorMessage
```

验收标准：

- `ReminderAudioPath` 指向 `audio/reminder.m4a`
- 正常播放时，`ReminderAudioStatus` 为 `played`
- 播放失败时，`ReminderAudioErrorMessage` 会留下错误文本

## 15. Options 设置页

1. 打开扩展选项页

验收标准：

- 显示极简统计和提醒设置
- 至少包含：
  - 今日阅读
  - 今日提醒
  - 阅读状态
  - 当前状态解释
  - 下次提醒
  - 页面支持
  - 页面可见
  - 当前计时
  - 最近操作
  - 倒计时推进
  - 提醒模式设置
  - 提醒间隔设置
  - 语音开关
  - 全屏提醒开关
  - 已启用站点列表
  - 导出 CSV

## 16. 已启用站点管理

1. 先通过 popup 为一个普通网页授权
2. 打开扩展选项页
3. 在 `已启用站点` 区域观察列表
4. 点击对应站点的 `移除`

验收标准：

- 列表中会显示已授权站点
- 默认的 `https://weread.qq.com/*` 不出现在可移除列表中
- 点击 `移除` 后，该站点会从列表中消失
- 移除后回到该站点，popup 再次显示 `在此站点启用护眼提醒`

## 17. 设置项即时生效

1. 打开扩展选项页
2. 先切到 `标准提醒`
3. 把提醒间隔切到 `15` 或 `30` 分钟
4. 切换语音开关
5. 切换全屏提醒开关
6. 再切回 `20-20-20`
7. 回到当前已启用页面，再点一次 `预览提醒`

验收标准：

- 设置修改后会立即保存
- 切到 `标准提醒` 后，提醒间隔选择可编辑
- 切回 `20-20-20` 后，提醒间隔选择会禁用，且实际节奏固定为 `20 分钟 + 20 秒倒计时`
- 改提醒间隔后，标准模式下 popup 的下次提醒时间会按新间隔变化
- 关闭语音后，预览提醒不再播放固定音频
- 关闭全屏提醒后，预览提醒改为右下角卡片，不阻塞底层页面
- 重新打开 options，设置值保持不变

## 18. 清空数据

1. 在扩展选项页点击 `清空本地统计`
2. 返回 popup 再查看状态

验收标准：

- 今日阅读时长清零
- 今日提醒次数清零
- 当前累计状态清零
- 提醒设置恢复默认值
- 重新开始阅读后，从新的累计周期开始

## 19. CSV 导出

1. 在扩展选项页点击 `导出 CSV`
2. 打开下载得到的文件

验收标准：

- 会下载一个 `.csv` 文件
- 文件名形如 `weread-eye-care-YYYY-MM-DD.csv`
- 表头固定为：
  - `date`
  - `domain`
  - `bookTitle`
  - `readingMinutes`
  - `reminderCount`
- 不包含眨眼率或恢复效果相关字段

## 20. 回归关注点

重点观察这些风险：

- 普通网页授权后是否真的只对当前域名生效
- popup 的下次提醒时间是否和实际累计节奏一致
- 页面隐藏或切标签页后是否真的暂停
- 预览提醒是否误计入真实提醒次数
- 固定音频在你的 Chrome 环境里是否稳定播放
